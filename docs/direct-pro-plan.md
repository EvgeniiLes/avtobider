# Профессиональная настройка Директа: план

Цель: чтобы рекламу малого бизнеса сервис настраивал так, как это делает опытный специалист по Директу. Модель не «пишет тексты», а проходит цепочку этапов, а код жёстко проверяет результат.

## Проверено по документации API (v501)
- Объявление (TextAd): `Title` до 56, `Title2` до 30, `Text` до 81 знака, `DisplayUrlPath` до 20 знаков (нужна `Href`), `AdExtensionIds` до 50, `SitelinkSetId`, `PriceExtension`, `VideoExtension`, `BusinessId` (профиль организации).
- Уточнения: `adextensions.add`, `Callout.CalloutText` до 25 знаков, до 1000 за вызов, одинаковые в одном запросе дают ошибку. Лимит на аккаунт: `Clients.get`, `Restrictions`, `AD_EXTENSIONS_TOTAL`.
- Виртуальные визитки (`VCardId`) устарели: значение не сохраняется. Адрес и телефон показывает профиль организации (`BusinessId`), он у нас уже подключён.
- Сети: у стратегии `Network.BiddingStrategyType` есть `SERVING_OFF`; `PlacementTypes` содержит `Network` и `Maps`. Ранее мы сознательно оставили `NETWORK_DEFAULT` (поиск, Карты, сайты-партнёры вместе): менять только после отдельного решения владельца.
- Группа объявлений: единственное гео-поле `RegionIds` (радиуса нет, см. docs/platforms.md).
- Не проверено: формат расписания показов (`TimeTargeting`), корректировки по устройствам, быстрые ссылки (нужны разные адреса страниц), частотность фраз (Wordstat / `keywordsresearch`).

## Этапы
1. **Дополнения объявления** (сделано, app/direct/extras.py): второй заголовок, уточнения, отображаемая ссылка. ИИ предлагает, код проверяет длины, знаки, ВЕРХНИЙ РЕГИСТР, числа и обещания без опоры на описание.
2. **Структура по намерениям**: группа на услугу («стрижка собак», «груминг кошек», «тримминг»), свои фразы и объявления; заголовок содержит искомое слово; перекрёстные минус-слова между группами.
3. **Проверяющий по модерации Директа**: отдельный ИИ-проход и код: запрещённые обороты, превосходная степень, регистр, знаки, длина; плохое не отправляем на проверку.
4. **Фразы с цифрами**: частотность (Директ или Вордстат), операторы (`!`, кавычки, `[]`), фразы из реальных запросов.
5. **Сети и график**: решение по сетям, расписание по часам работы, корректировки по устройствам и районам (после проверки полей API).
6. **Оптимизация по данным**: статистика по фразам, устройствам и часам (сбор уже есть в app/direct/slices.py), отключение дорогих фраз без обращений, корректировки.

## Как сделать модель «профи»
Цепочка вместо одного промпта: аналитик (сегменты и намерения) → медиапланер (структура кампании) → копирайтер → проверяющий по правилам Директа → валидатор в коде. Для планировщика и проверяющего подходит более сильная модель (Opus 5.5), для остального Sonnet 5.5. В системные промпты кладём чек-лист Директа и правила модерации.
